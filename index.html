Revisión y explicaciones

Basado en los apuntes de Administración de Sistemas · UCAM. Material de estudio personal.

📋 Chuleta rápida

Tema 1 · Sistemas de Información

  • SI: captura, almacena y transforma datos para entregar información oportuna y precisa.
  • Dato: hecho sin procesar. Información: dato con relevancia. Conocimiento: experiencia, mente humana.
  • 9 características: exactitud, comprensión, completitud, economicidad, confianza, relevancia, nivel de detalle, oportunidad, verificabilidad.
  • 3 dimensiones: humana, tecnológica, organizativa.
  • CPD: equipamiento + energía redundante + control ambiental + seguridad.
  • Evolución: mainframes → minis → cliente-servidor → grid (90s) → clústers → virtualización → nube → CPD modular (2007).
  • DevOps (2008): acerca desarrollo y sistemas; automatización; dev = producción.

Tema 2 · Virtualización

  • VM: hardware simulado + SO + apps, aislada. Hipervisor: desvincula VM del host y asigna recursos.
  • Tipo 1: sobre hardware (ESXi). Tipo 2: sobre SO anfitrión (Workstation, VirtualBox).
  • Tipos: plataforma (completa, paravirtualización, SO), recursos (swap, VPN), aplicaciones (Wine, JVM, CLR), escritorio (Citrix).
  • Ventajas: consolidación, administración simple, HA, rendimiento/redundancia, coste, energía.
  • Inconvenientes: pérdida de rendimiento, monitorizar el host, hardware no soportado, mala densidad, host = punto único de fallo.
  • Ficheros VMware: .vmx configuración, .nvram BIOS, .vmdk disco, .vmsd snapshots, .vmsn estado.
  • Hiperconvergencia III: local + SDS, sin SAN; flash para caliente, HDD para frío.

Docker

  • Imagen: plantilla de solo lectura. Contenedor: instancia ejecutable. Al ejecutar una imagen nace un contenedor.
  • Dockerfile: FROM al inicio, CMD al final; cada instrucción = una capa; solo se reconstruyen las cambiadas.
  • Build: docker image build -t nombre .
  • Registro: Docker Hub por defecto; pull descarga, push sube.
  • Persistencia: volúmenes (fuera del UFS) y bind mounts (directorio del host). Los bind mounts no van en el Dockerfile.
  • Ventajas: CI/CD, portabilidad, entornos consistentes, más cargas por hardware, ligero.
  • Ojo: contenedor ≠ mini VM; comparte kernel y es un proceso.

Tema 3 · Dominios y AD

  • Grupo de trabajo: BD local por equipo, descentralizado, sin Windows Server; problema: sincronizar usuarios.
  • AD: servicio de directorio de Microsoft basado en X.500; objetos + GPO.
  • Jerarquía: OU ⊂ dominio ⊂ árbol ⊂ bosque. Dominio = frontera de seguridad; árbol = namespace contiguo; bosque = árboles con confianza.
  • Nombres: DN (ruta completa), RDN (sin dominio/OU), UPN (usuario@dominio), SID (cambia de dominio), GUID (nunca cambia), NetBIOS (compatibilidad).
  • CD: autentica y replica. RODC: solo lectura, sucursales, no tolerancia a fallos.
  • GPO: máquina al arrancar, usuario al logon; refresco 90 ± 30 min (DC 5 min); seguridad 16 h; orden Sitio > Dominio > OU > Grupo > Equipo > Usuario; gana la más específica.
  • Tiempos AD: intra-sitio 15 s (pausa 3 s); entre sitios 180 min (mín. 15); KCC 15 min; tombstone 180 días; GC 12 h.
  • PowerShell: orientado a objetos; MONAD 2003 → PowerShell 2006 → Core 2016; alias dir/ls/gci.

Clústers · tabla de bolsillo

  • HPC: minimiza latencia/TTS; tareas fuertemente acopladas; MPI, InfiniBand, Slurm/PBS, GPU/FPGA.
  • HTC: maximiza throughput; tareas independientes; HTCondor, checkpointing, Grid Engine; no necesita red de ultrabaja latencia.
  • Cómo decidir: si las tareas se comunican y sincronizan en cada paso → HPC; si son independientes y prima completar muchas por hora → HTC.
  • HA: continuidad y failover; RTO (tiempo de recuperación) y RPO (datos perdidos) ≈ 0; quórum y fencing evitan split-brain; activo-pasivo vs activo-activo; Pacemaker (recursos) + Corosync (heartbeat); VIP flotante; failback.
  • LB: reparte tráfico entrante; L4 (IP/puerto) vs L7 (contenido HTTP); sticky sessions y health checks; Round-Robin, Weighted Round-Robin (estático) y Least Connections (dinámico); HAProxy, NGINX Plus.
  • Almacenamiento: SDS; Ceph (S3, RBD, CephFS), GlusterFS (hasta 16 EB, mal rendimiento de metadatos); elegir por perfil de E/S.
